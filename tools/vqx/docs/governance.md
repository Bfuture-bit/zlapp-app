# VQX governance draft

VQX 0.x remains experimental. The following rules apply immediately and are intended to become the basis of a public RFC process.

- Published byte meanings are never silently changed within a version.
- Breaking semantic/wire changes require a new protocol version.
- Historical version manifests and release archives remain addressable.
- Security-relevant behavior must be covered by conformance tests.
- New control opcodes require a threat-model update.
- Experimental extensions must use versioned identifiers.
- Reference implementations do not define authorization policy.
- Benchmark claims must publish units, inputs, comparison format, and reproducible methodology.
- A future 1.0 release should require multiple independent implementations and external security review.

Before VQX is proposed as an official extension in another standards project, governance, licensing, maintainer identity, compatibility policy, and independent implementation requirements should be aligned with that project's rules.
